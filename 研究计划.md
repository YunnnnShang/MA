# Main Objective

This study aims to construct an energy modeling method based on HEVC software encoder features for accurately estimating the system-level energy consumption of the NVENC hardware encoder of the NVIDIA Jetson platform in intra-frame encoding mode. By introducing an interpretable machine learning model, this study explores the correlation between software encoding behavior and black-box hardware power consumption, providing theoretical and methodological support for subsequent hardware-software co-optimization and low-power video processing system design.

# Sub-Objectives

| Nr.  | Content                                                                                   |
| ------ | ------------------------------------------------------------------------------------ |
| **O1** | Extract features closely related to the complexity of intra-frame coding in the x265 software encoder, including prediction mode, CU partition structure, residual information, and image content features, and construct a feature set |
| **O2** | Intel RAPL and LMG611 are used to obtain accurate energy consumption data during software and hardware encoding, respectively, and a reproducible energy consumption collection platform is established.                           |
| **O3** | Use machine learning methods such as XGBoost to map software features to hardware energy consumption and build an accurate power consumption estimation model with an error rate of less than **5%**。                     |
| **O4** | Compare multiple regression models (such as XGBoost, Linear Regression, MLP, SVM) and perform ablation studies to verify the importance of each feature and the sensitivity of model performance. |
| **O5** | Analyze the interpretability of the model, clarify which encoding behaviors have the most significant impact on power consumption, and assist in understanding the software-hardware coupling mechanism.                               |
| **O6** | Evaluate the generalization and robustness of the model on different QP values, resolutions, preset parameters, and video content.       |
| **O7** | Visualize the trends of hardware and software power consumption as a function of encoding configurations (e.g., QP, content complexity) and analyze coupling/inconsistency between them.                                |

# Model selection
| Model                | Features            | Plan           |
| ----------------- | ------------- | -------------- |
| **XGBoost**       | High accuracy and good interpretability      |  baseline    |
| **Random Forest** | High tolerance to feature redundancy and nonlinearity | Can be used as a baseline for comparison|
| **MLP**    | Can model complex feature interactions | Try it when there are many features     |
| **SVR**           | Stable for small data sets | Can be used as a control group if the sample size is small  |

# Evaluation Metrics

| Metric Type |  Metric Name  | Description                    |
| --------- | ------------------------- | --------------------------- |
| **Prediction Accuracy** | MAE, MAPE, RMSE | Used to evaluate the accuracy of the model's prediction of energy consumption, with the goal of MAPE ≤ 5% |
| **Generalization** | Cross-domain Accuracy | Evaluate the model's prediction ability for unseen QP, content, preset |
| **Interpretability** | SHAP / Feature Importance | Quantify the contribution of each feature to the model output |
| **Comparative Analysis** | Multi-model comparison | Verify the performance and complexity tradeoff of different models |
| **Trend consistency** | Pearson/Spearman correlation coefficient | Measure whether the software energy consumption trend can explain the hardware energy consumption change |

软件端: 在你的x86 Linux系统上，准备好x265编码器。编写一个自动化脚本（Python或Bash），该脚本可以：

循环执行x265命令，遍历不同的视频序列、分辨率和配置（QP值、presets）。

在x265运行时，同步启动Intel RAPL的测量脚本来记录CPU和DRAM的能耗。

同时，使用perf stat -p <x265_pid> -e <event1>,<event2>...来记录关键的处理器事件。

确保使用x265 --csv参数将编码统计数据保存到文件中。

硬件端: 在Jetson平台上，准备好你的外部功率计（LMG611）。同样编写一个自动化脚本，可以：

调用ffmpeg或GStreamer框架来使用NVENC硬件编码器进行编码。

同步触发LMG611开始和停止测量，并将数据记录下来。

进行配置匹配研究:

仔细阅读我为你提供的x265和NVENC文档，特别是关于帧内编码（Intra-coding）和性能/质量权衡（preset/tuning）的部分。

制作一张参数映射表，尝试将x265的关键帧内编码参数与NVENC的API选项对应起来。

数据收集与模型训练:

在两个平台上运行你定义的匹配配置，收集所有数据（软件能耗、PEs、编码统计、硬件能耗）。

将数据对齐（例如，按帧或按视频序列）。

从最简单的线性回归模型开始，复现论文中的思想，用你的x265测量数据作为输入，硬件能耗作为输出来训练模型，并评估其准确性。
